# World

> Requirement quotes on this page were read from the published prize page on 2026-09-05; that day's saved copy is kept privately with its hash. Where an older fetch is carried forward, the file says so.


**Touches UNICA today:** nothing in the tree. A seam was designed and not built: gating a
discounted settlement behind one World ID credential per person ("one human, one discounted
settlement"). It is recorded as a seam, never as an integration.

**Published requirement** (Selfie Check, ethglobal.com/events/ethonline2026/prizes, retrieved
2026-09-05): "Uses Selfie Check or a Selfie Check-compatible World ID credential flow in a
meaningful way."

**What would have to be built:** an actual credential check gating a real product behavior —
not a badge that changes nothing. This was not attempted. Selfie Check is currently gated
behind a per-app email request to World, and sandbox testing needs a private build World
issues; neither is self-serve, and only the project owner can request either.

**What we'd ask World to change, with evidence:** their Selfie Check developer page
(docs.world.org/world-id/idkit/credentials, fetched 2026-09-04) documents the client-side
preset and its parameters, then instructs the developer to forward the result to "the
verification endpoint" without naming that endpoint's URL, request body, or response fields.
The word "nullifier" does not appear on the page at all — so the one property a
one-human-one-benefit product depends on, whether and how replay is prevented, is undocumented.
We would ask for the endpoint's request/response shape and one paragraph on nullifier scope.

Status: no claim of qualification.
