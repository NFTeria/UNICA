# ENS

> Requirement quotes on this page were read from the published prize page on 2026-09-05; that day's saved copy is kept privately with its hash. Where an older fetch is carried forward, the file says so.


**Touches UNICA today:** nothing in the tree. UNICA's settlement flow has no naming layer;
orders and receipts are addressed by raw addresses and order ids.

**Published requirement** (Best Use of ENSv2, ethglobal.com/events/ethonline2026/prizes,
retrieved 2026-09-05): "ENSv2 features should be central to the product."

**What would have to be built:** an ENSv2 (Sepolia) integration where resolution or naming is
central to the settlement flow, not decorative — for example, resolving an order's recipient
through an ENSv2 name instead of a raw address. Nothing toward this was attempted, and the
surface was not independently swept for a documentation or interface gap this pass.

**What we'd ask ENS to change:** no request. No ENSv2 defect was established, and a proposal
without one would be speculative. A text-record-based agent binding under ENSIP-25/26 was
considered and set aside: both ENSIPs are still Draft status, and a record set once and read by
a demo interface keeps nothing durable.

Status: no claim of qualification.
