# Privy

> Requirement quotes on this page were read from the published prize page on 2026-09-05; that day's saved copy is kept privately with its hash. Where an older fetch is carried forward, the file says so.


**Touches UNICA today:** nothing in the tree. Two seams were designed and neither was built: a
Privy-funded wallet as the payer on the demo surface, and a wallet approval control on an
operator wallet used for admin funds.

**Published requirement** (Best Financial Flow, ethglobal.com/events/ethonline2026/prizes,
retrieved 2026-09-05): "Integrate Privy as a core part of the product."

**What would have to be built:** frontend wiring so a Privy wallet funds and signs the demo
surface's swap, or a Privy-gated approval step on the project's own operator wallet. Neither
exists today. The first needs a dashboard app id and no secret; the second needs a dashboard
app id and secret, both an owner-only dependency. Neither is a fix to anything broken upstream
— both are additive frontend seams with no defect behind them.

**What we'd ask Privy to change:** no request. Nothing encountered while designing these seams
pointed at a documentation or interface gap on Privy's side.

Status: no claim of qualification.
