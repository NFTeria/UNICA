Identical to the 2026-09-04 pass: one live hit, one archived hit, and `HookMiner` exists

## Expected behaviour

The deployment guide's `import {HookMiner} from "v4-periphery/src/utils/HookMiner.sol";`
resolves, and `forge script` mines a salt for the hook address as the guide walks through.

## Actual behaviour

The import does not resolve — `v4-periphery` has no `src/utils/` directory on `main` — and
the guide's own linked deep-link to that path also 404s. The build fails at the one step a
v4 hook cannot skip: mining a valid hook address.

## Minimal command or test

```sh
gh api repos/Uniswap/v4-periphery/contents/src/utils                       # 404
gh api 'repos/Uniswap/v4-periphery/git/trees/main?recursive=1' \
  --jq '.tree[].path' | grep -i hookminer                                   # test/shared/ only
```

## Impact

Every reader following this guide top-to-bottom cannot mine a hook address without first
discovering, unassisted, that the import has moved to `test/`, which is not conventionally
a package's importable public surface (see the related placement question in
`docs/INTEGRATIONS.md` rank 11, not drafted here).

## Proposed correction

Point the import and the deep-link at `v4-periphery/test/shared/HookMiner.sol`, with one
sentence noting that `test/shared` is not a stable public surface and that `v4-periphery`
publishes zero tags and zero releases, so any pin should be to a commit SHA. Alternatively
point at `hookmate`, which republishes the miner behind a maintained package. This
correction should travel with the rank-1 draft (`01-basehook-import-path-docs.md`) as one
PR against the same guide family, since both are `content/` import-path corrections.
