# The v4 template's only CI workflow has its `push` and `pull_request` triggers commented out

## Affected official repository and version

`github.com/Uniswap/v4-template`, `.github/workflows/test.yml` (the repository's only
workflow file), commit `1fbf95547791f0821a170b88c750cb2e04e6818b` (main, read
2026-09-05T16:47:15Z).

## Exact reproduction

Re-run today, 2026-09-05:

```
$ gh api repos/Uniswap/v4-template/contents/.github/workflows/test.yml --jq '.content' \
    | base64 -d | sed -n '1,14p'
name: Test Suite

on:
  workflow_dispatch:
  # push:
  # pull_request:

env:
  FOUNDRY_PROFILE: ci

jobs:
  test:
    name: Foundry Project
    runs-on: ubuntu-latest
```

Byte-for-byte identical to the 2026-09-04 finding: `on:` declares only
`workflow_dispatch:`; the `push:` and `pull_request:` lines are present but commented out.

## Expected behaviour

A fork of the recommended v4 starting point runs its test suite automatically on every
push and pull request, as the file's own `name: Test Suite` and `FOUNDRY_PROFILE: ci`
imply.

## Actual behaviour

The workflow runs only on manual `workflow_dispatch`, which essentially nobody triggers by
hand. A fork shows a workflows tab and looks like it has CI, while no test ever runs
automatically on a commit.

## Minimal command or test

```sh
gh api repos/Uniswap/v4-template/contents/.github/workflows/test.yml --jq '.content' \
  | base64 -d | grep -n "push:\|pull_request:\|workflow_dispatch:"
```

## Impact

This is the repository the track recommends as a starting point. A hackathon entrant who
forks it and starts committing gets no automatic CI feedback at all, and a workflow file
that reads as coverage while providing none is arguably worse than no file, because its
presence discourages a fork's author from adding a working one themselves.

## Proposed correction

Uncomment the two trigger lines. If the triggers are deliberately disabled to save Actions
minutes across a very large number of forks, one comment line saying so would turn a
puzzling omission into a stated trade-off; the PR should be framed as a question rather
than an assertion, since no linked issue or commit message explaining the current state was
found.

## Classification

documentation ambiguity — properly, a workflow-configuration ambiguity: the file's own name
and environment variable imply automatic CI, and the triggers say otherwise, with no stated
reason recorded anywhere in the repository for the mismatch.
