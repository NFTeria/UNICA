Seven of the fourteen hits are under `content/` (live docs); the other seven are under
`archive/`, which `CONTRIBUTING.md` excludes from the accepted-PR surface. All counts and
the 404 match the 2026-09-04 research pass exactly — nothing has changed on either
repository's `main` in the intervening day.

## Expected behaviour

A reader copies `import {BaseHook} from "v4-periphery/src/utils/BaseHook.sol";` from any of
the seven live guides, runs `forge build`, and the hook compiles.

## Actual behaviour

solc cannot resolve the path. `v4-periphery` has no `src/utils/` directory at all on `main`
(HTTP 404), and no file named `BaseHook.sol` exists anywhere in the repository's tree.
`BaseHook`'s real home today is `OpenZeppelin/uniswap-hooks`, `src/base/BaseHook.sol`.

## Minimal command or test

```sh
gh api repos/Uniswap/v4-periphery/contents/src/utils   # 404 confirms the path is gone
gh api -X GET search/code -f q='"v4-periphery/src/utils/BaseHook.sol" repo:Uniswap/docs'
                                                        # confirms which files still teach it
```

## Impact

Seven live, current-generation guides — the first-hook walkthrough, the getting-started
page, and five hook-pattern guides — hand a new v4 hook author an import that cannot
resolve at the very first `forge build`. This is the guide the track's own resource block
points hackers at.

## Proposed correction

One line per file, seven files, one PR:
`import {BaseHook} from "@openzeppelin/uniswap-hooks/src/base/BaseHook.sol";`
plus one sentence in each file (or a single shared callout) stating that v4-periphery no
longer ships `BaseHook` and naming the OpenZeppelin package as its current home. This is
complementary to the already-open PR #1116, which touches only
`docs/contracts/v4/quickstart/hooks/setup.mdx` — a path now under `archive/` — and has been
open and unmerged since 2026-04-26.
