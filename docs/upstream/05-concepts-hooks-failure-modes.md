# The `concepts/hooks` page documents one of three permission failure modes and never mentions `CurrencyNotSettled`

## Affected official repository and version

`github.com/Uniswap/docs`, `content/protocols/v4/concepts/hooks.mdx`, commit
`1c7597d73be0e9a3a4e44aa75b8fb212b40ea136` (main, read 2026-09-05T16:47:12Z).

## Exact reproduction

Re-run today, 2026-09-05:

```
$ gh api repos/Uniswap/docs/contents/content/protocols/v4/concepts/hooks.mdx \
    --jq '.content' | base64 -d > hooks_mdx_check.txt
$ wc -l hooks_mdx_check.txt
60 hooks_mdx_check.txt

(no output — zero matches)
```

The page is 60 lines today; `CurrencyNotSettled` does not appear anywhere in it, matching
the 2026-09-04 finding exactly.

## Expected behaviour

A page whose subject is hook permissions and their failure modes documents what happens in
each of the three ways a hook's declared permissions can diverge from its actual behaviour.

## Actual behaviour

The page states only the silent-no-op case ("If the address lacks a flag, the PoolManager
never calls that hook function, so the logic silently does nothing") and the
deployment-time address-mismatch case. It says nothing about a delta returned without the
matching returns-delta permission bit, which produces `IPoolManager.CurrencyNotSettled`
(selector `0x5212cba1`) — the failure mode a hook author is most likely to hit once the
hook does something beyond a no-op, and the one this project's own spec calls "the bug that
silently eats hooks."

## Minimal command or test

```sh
gh api repos/Uniswap/docs/contents/content/protocols/v4/concepts/hooks.mdx --jq '.content' \
  | base64 -d | grep -ic currencynotsettled     # 0
```

## Impact

A hook author who reads this page as the complete failure-mode reference and ships a hook
that returns a delta without the matching permission bit gets `CurrencyNotSettled` at swap
time with no page connecting the error to its cause. The silent case the page does document
is, by the page's own framing, the hardest to catch because nothing goes red — but the
returns-delta case is arguably worse, because it goes red at the wrong layer (a revert deep
in settlement) with no documented link back to the missing bit.

## Proposed correction

One three-row table added to the page, sourced from this project's own spec (see below),
purely additive:

| Mismatch | Result |
|---|---|
| Permission bit set, callback missing | revert |
| Callback implemented, permission bit missing | silent no-op |
| Returns-delta bit missing while returning a delta | `CurrencyNotSettled` |

## Evidence generated by UNICA (file:line in this repository)

`specs/HOOK-SPEC.md:177-185` — "§5 — The flag trap (the bug that silently eats hooks)"
already carries this exact three-row table, with its own incident citations (Sorella
Angstrom, and a live Crypto-UPI hook with the same shape). The silent-no-op case is guarded
directly: `test/V4SettlementHook.t.sol:45` (`test_MinedAddress_MatchesDeclaredPermissions`),
`:50` (`test_NoUndeclaredPermissionsCreepIn`), `:61` (`test_RevertWhen_AddressBitsSayBeforeSwapOnly`),
`:67` (`test_RevertWhen_AddressBitsSayAfterSwapOnly`) — all pass today. The returns-delta
case's underlying failure mode is exercised in `test/I7NativeSettle.t.sol:69`
(`test_I7_DefenceOff_ForeignSync_Reverts`) and `:99` (`test_I7_DefenceOn_ForeignSync_Survives`).
The 2026-09-04 FEEDBACK.md entry ("`v4-security-foundations` run over the real gate and
router") already logs the silent-permission-bit failure mode first-hand as "the failure our
T5 guard exists for"; this draft only extends that finding to the `CurrencyNotSettled` case
and to this specific page.

## Classification

documentation ambiguity — no statement on the page is wrong, but the coverage of a stated
subject (hook permission failure modes) is incomplete in a way that costs a reader real
debugging time on the failure they are least likely to expect.
