# `uniswap-hooks` plugin's base hook template imports `BaseHook` from a path that never existed on main, and uses a removed `IPoolManager.SwapParams` type

## Affected official repository and version

`github.com/Uniswap/uniswap-ai`,
`packages/plugins/uniswap-hooks/skills/v4-security-foundations/references/base-hook-template.md`,
commit `936734cdc8e704b1fdcce3211d9e6215cd10da7f` (main, read 2026-09-05T16:47:10Z).


Both defects are unchanged from the 2026-09-04 pass: the template is still on `main`
today, verbatim, with both broken references.

## Expected behaviour

A hacker following the track's own linked tool (`uniswap-ai`, installed as the
`uniswap-hooks` plugin) runs `v4-security-foundations`, gets a template, pastes it into a
Foundry project, and it compiles as a starting point.

## Actual behaviour

It does not compile. Line 11's `BaseHook` import 404s — no `BaseHook.sol` exists anywhere
in `v4-periphery` at any path, so unlike the docs guides (rank 1) there is no working
`v4-periphery` path to fall back to at all. Separately, three call sites reference
`IPoolManager.SwapParams`, a type that in the pinned `v4-core` commit `d153b04` is declared
in `src/types/PoolOperation.sol` and does not exist inside `IPoolManager`.

## Minimal command or test

```sh
gh api 'repos/Uniswap/v4-periphery/git/trees/main?recursive=1' --jq '.tree[].path' \
  | grep -i basehook                                    # empty: no BaseHook.sol anywhere
grep -c "struct SwapParams" lib/uniswap-hooks/lib/v4-core/src/interfaces/IPoolManager.sol
                                                          # 0: not declared inside IPoolManager
```

## Impact

A tool shipped specifically to generate hooks emits code that cannot compile, on the exact
stack the same monorepo's own `v4-hook-generator` skill would hand to the same user in the
adjacent step. This is the template a security-focused skill hands out as the starting
point for a hook a developer is about to trust with funds.

## Proposed correction

Two lines in one file: correct the `BaseHook` import to
`@openzeppelin/uniswap-hooks/src/base/BaseHook.sol`, and correct the three `SwapParams`
references to import `SwapParams` from `v4-core/src/types/PoolOperation.sol` rather than
qualifying it off `IPoolManager`. One comment naming the `v4-core` commit the types come
from would prevent the same drift recurring.

## Classification

defect — the template as published cannot compile against the current public v4-periphery
and v4-core, on any stack; there is no version of `v4-periphery` main at which the `BaseHook`
import resolves.
